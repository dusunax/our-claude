# store-listing-assets

앱을 Google Play 스토어에 등록할 때 Play Console이 요구하는 **그래픽 에셋과 등록 문구**를 만든다. 실제
앱 화면을 캡처해서 캡션과 함께 스토어 규격 이미지로 조립하고, 앱의 실제 카피(README·랜딩 문구)로 등록
문구를 쓴다. 특정 앱에 묶이지 않는다.

> **먼저 `promo-studio` 스킬을 따른다.** Remotion 프로젝트 구조(`shared/` + `<app-name>/`), 산출물
> 파일명(`YYMMDD_<프로젝트>_<항목>`), 화면 캡처(특히 **3x 고해상도 캡처**), 폰트, 정지 이미지 렌더,
> 검증·전달은 그쪽에 있다. 이 문서에는 **스토어 에셋에만 해당하는** 규격과 배치 규칙을 둔다.

## 언제 쓰나

- "스토어 리스팅 에셋 만들어줘", "플레이스토어 스크린샷/아이콘/피처 그래픽", "스토어 등록 문구"를
  요청받았을 때.
- 앱을 TWA 등으로 Play 스토어에 올리는 작업의 리스팅 단계(아이콘·스크린샷·문구 준비).
- 쇼츠/릴스 홍보 영상은 `shorts-promo-video`를 쓴다. 같은 Remotion 프로젝트·같은 캡처를 재사용할 수 있다.

## 규격

| 항목 | 규격 | 비고 |
| --- | --- | --- |
| 앱 아이콘 | 512×512 PNG, 1MB 이하 | 모서리 둥글리기·그림자는 스토어가 처리한다 — 정사각형으로 꽉 채운다 |
| 피처 그래픽 | 1024×500 PNG/JPG (알파 없음) | 스토어에서 가장자리가 잘려 노출될 수 있어 핵심은 안쪽에 |
| 휴대전화 스크린샷 | 2~8장, 한 변 320~3840px, **긴 변이 짧은 변의 2배 이하** | 9:16(1080×1920) 권장, 알파 없음 |
| 앱 이름 | 30자 이내 | |
| 간단한 설명 | 80자 이내 | |
| 자세한 설명 | 4000자 이내 | |

수치는 작성 시점 기준이다. **Play Console의 입력 화면 안내가 최종 기준**이니 등록 전에 한 번 대조한다.

**긴 변이 짧은 변의 2배 이하** 조건 때문에 최신 폰 화면비 캡처(430×932 → 2.17배)는 그대로 못 올린다.
캡처 그대로가 아니라 캡션 영역과 여백이 있는 9:16 캔버스(1080×1920) 안에 넣는다.

## 절차

### 1. 공통 준비 (`promo-studio`)

`src/<app-name>/`과 `public/<app-name>/`을 준비하고, 컴포지션은 `src/<app-name>/store/StoreAssets.tsx`에
둔다. id는 `<App>StoreIcon`, `<App>FeatureGraphic`, `<App>StoreShot1`~`N`처럼 앱 접두사를 붙이고
`Root.tsx`의 `<Folder name="<app-name>">` 안에 등록한다.

### 2. 실제 화면 3x 캡처

`promo-studio`의 "고해상도(3x) 캡처"로 `public/<app-name>/store-src/`에 저장한다(1290×2796).
스토어 스크린샷은 **배포된 앱을 실제로 플레이하며** 찍는 게 가장 사실적이다. 보여줄 장면 4~5개를 정한다:

- 시작/랜딩 화면
- 핵심 설정·선택 화면
- **결과 화면(가장 중요)** — 앱의 차별점이 드러나는 장면
- 기록·통계 등 보조 화면(비어 보이면 제외한다)

결과 화면은 **입력 하나만 넣고 찍는다.** 여러 번 진행한 채로 찍으면 스크롤 때문에 위에 이전 카드가 반쯤
잘려 보인다. 앱에 성격·모드 같은 선택지가 있으면 캡션과 어울리는 걸로 고른다(예: "바퀴벌레가 나타났다!"
→ 겁이 많은 유형은 숨는다).

### 3. 컴포지션 작성

- **앱 아이콘**: 512×512. 앱의 대표 캐릭터/심볼 하나를 가운데에 크게(폭 약 70%), 브랜드 색 방사형
  그라데이션 위에 둔다. 글자는 넣지 않는다. **스프라이트 원본이 작으면(≈120px) 확대 시 부드럽게
  보인다** — 벡터/고해상도 원본이 있으면 그걸 쓰고, 없으면 그 한계를 사용자에게 알린다.
- **피처 그래픽**: 1024×500. 앱의 실제 배경 이미지를 깔고 왼쪽에 앱 이름(크게)·한 줄 카피를 둔다.
  글자 쪽에는 크림색 그라데이션 오버레이로 가독성을 확보하고, 오른쪽에 캐릭터와 소품을 둔다.
  텍스트는 좌우 60px 이상 안쪽에 둔다.
- **휴대전화 스크린샷** (`<App>StoreShot`, props: `shot`, `line1`, `line2`): 1080×1920 캔버스에
  `backdropBackground` 위 **캡션 2줄(1줄 진한 색, 2줄 브랜드 강조색) + 폰 프레임(흰 테두리·둥근 모서리·
  그림자)** 안에 캡처를 넣는다. 캡처의 비율(430:932)을 그대로 지켜 `object-fit: cover`로 늘어남·잘림이
  없게 한다.
  - **위아래 여백을 넉넉히**: 캡션은 위에서 약 120px, 폰 프레임 아래는 100px 이상 남긴다(프레임 높이
    약 1350px). 프레임이 화면 가장자리에 붙으면 스토어 UI에서 답답하고 잘려 보인다.
  - 캡션은 "무엇을 하는지" 또는 "궁금증을 부르는 상황"으로, 한 줄 14자 안팎이 읽기 좋다.
- 여러 장은 한 컴포넌트에 props만 바꿔 `storeShots` 배열로 `<Composition>`을 반복 등록한다.
  props 타입은 `type` 별칭으로 선언한다(`promo-studio` "정지 이미지 렌더" 참고).

### 4. 렌더 및 검증

```bash
cd tools/promo-studio
npx remotion still src/index.ts <App>StoreIcon out/<YYMMDD>_<app-name>_icon-512.png --frame=0
npx remotion still src/index.ts <App>FeatureGraphic out/<YYMMDD>_<app-name>_feature-graphic-1024x500.png --frame=0
npx remotion still src/index.ts <App>StoreShot1 out/<YYMMDD>_<app-name>_screenshot-1.png --frame=0
```

`file`로 픽셀 크기를 확인하고(512×512, 1024×500, 1080×1920), **모든 이미지를 Read 도구로 직접 본다.**
위아래 여백, 캡션 줄바꿈, 앱 화면이 잘리지 않았는지, 아이콘이 흐리지 않은지 확인한다. PNG는 알파 없는
RGB로 나오므로 별도 처리는 필요 없다.

### 5. 등록 문구

앱의 실제 카피·README를 재료로 `<YYMMDD>_<app-name>_listing-copy.md`에 정리한다:

- **앱 이름**(30자 이내): 랜딩에 쓰인 이름 그대로.
- **간단한 설명**(80자 이내): 앱의 핵심 동작 한 문장. 랜딩 카피가 있으면 그걸 활용한다.
- **자세한 설명**(4000자 이내): 앱이 실제로 하는 것만 쓴다. 상황 예시 한두 줄로 시작하고, 기능을
  `■ 제목` + 2~3줄 단위로 나열한다. **README에 없는 기능은 쓰지 않는다.**
- **데이터·AI 고지**: 입력한 텍스트가 외부 API(LLM 등)로 전송되거나 기기에 저장되면 자세한 설명 끝에
  한 줄 고지하고, 개인정보처리방침·Data Safety 양식과 내용이 일치하는지 함께 확인하도록 안내한다.
- 파일 끝에 에셋 목록 표(항목·파일명·규격)를 둔다.

### 6. 전달

`promo-studio`의 "검증과 전달"대로 `SendUserFile` 또는 경로 안내로 넘긴다. 이 에셋 폴더(`out/`)는
커밋하지 않는다.

## 알려진 함정

- **1x 캡처를 1080px 캔버스에 확대** — 글자가 뭉개진다. 3x로 다시 찍는다.
- **430×932 캡처를 그대로 업로드** — 긴 변/짧은 변 2배 제한을 넘어 반려된다. 9:16 캔버스에 넣는다.
- **결과 화면을 여러 번 진행한 뒤 촬영** — 위에 이전 카드가 잘려 보인다. 입력 하나만 넣고 찍는다.
- **폰 프레임이 캔버스 가장자리에 붙음** — 위 120px·아래 100px 이상 여백을 둔다.
- **작은 스프라이트로 만든 아이콘이 흐림** — 원본 해상도 한계를 알리고 고해상도 원본을 요청한다.
- **README에 없는 기능을 설명문에 씀** — 지어내지 않는다.
- 공통 함정(`<Still>` frame 0, `interface` props 타입 오류, 폰트, 줄바꿈)은 `promo-studio` 참고.
